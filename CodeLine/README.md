# 代码行统计工具 (Lines of Code Counter)

统计指定目录下 **C / C++ / Java / Python** 源文件的文件数、空行数、注释行数、代码行数，并按语言分类汇总输出。

## 浏览器版

打开同目录下的 `网页统计.html`，选择要统计的文件夹即可查看结果。浏览器版使用 JavaScript 在本机处理所选源码，不会上传文件；支持 C、C++、Java、Python，统计口径与下方命令行版一致。通过个人主页访问时，文件夹选择在支持该功能的现代浏览器中可用。

## 一、运行效果

```
$ loc samples
---------------------------------------------------------------
Language              files       blank     comment        code
---------------------------------------------------------------
C                         1           2           4           6
C++                       1           2           6           9
Java                      1           1           4           6
Python                    1           5           5           5
---------------------------------------------------------------
SUM                       4          10          19          26
---------------------------------------------------------------
```

## 二、输入 / 输出设计

- **输入**：命令行指定目录名；**如果没有指定，则默认当前目录**。
- **输出**：如上表格，按 `C → C++ → Java → Python` 固定顺序输出，最后一行 `SUM` 为总计。

## 三、命令行用法

```
loc                 统计当前目录
loc <目录>          统计指定目录（递归含所有子目录）
loc <目录> -s       简化模式：blank / comment 两列输出 "/"（对齐课件 UI）
loc -h              显示帮助
```

> 课件截图里 `blank`、`comment` 两列是 `/`，属于该阶段的占位设计。
> 本程序默认把这两列的真实值算出来（更有用）；如果作业要求严格照截图输出，
> 加上 `-s` 参数即可得到完全一致的表格。

### 统计整个磁盘

```
loc C:\            统计整个 C 盘
loc D:\            统计整个 D 盘
```

整盘扫描是可以的，但有几点要知道：

- **耗时较长**：需要遍历全盘目录并逐个读取源文件，通常需要几分钟，
  具体取决于磁盘上的文件数量。扫描期间没有进度提示，属正常现象。
- **权限**：`C:\System Volume Information`、`C:\$Recycle.Bin` 等系统目录
  会因权限不足被自动跳过，不计入结果，这不是 bug。
- **深度**：程序已启用 `\\?\` 长路径前缀，超过 260 字符的深层目录也能正常访问
  （Windows 上默认的 `MAX_PATH` 限制已被绕过）。
- **只会统计源码**：只有 `kLangExt` 中登记过的扩展名才会被计数、打开，
  其余文件（`.dll`/`.exe`/`.png` 等）只参与目录遍历，不读取内容。

## 四、编译

程序仅依赖 **C++11 标准库 + 系统目录 API**，没有使用 `std::filesystem`，
所以 **Dev-C++(TDM-GCC 4.9)、MinGW、MSVC、GCC、Clang 都能直接编译**。

| 环境 | 命令 |
| --- | --- |
| MinGW / GCC / TDM-GCC | `g++ -std=c++11 -O2 -o loc.exe loc.cpp` |
| MSVC (命令行) | `cl /EHsc /O2 /Fe:loc.exe loc.cpp` |
| Make | `make` |
| Windows 一键 | 双击 `build.bat` |
| Dev-C++ | 新建项目 → 加入 `loc.cpp` → 编译运行（需在「工具→编译选项」勾选 C++11） |
| Visual Studio | 新建空项目 → 添加 `loc.cpp` → 生成 |

## 五、统计口径（判定规则）

### C / C++ / Java

| 情况 | 归类 |
| --- | --- |
| 整行只有空白字符 | `blank` |
| 行内含有任意有效代码（**行尾注释也算代码**） | `code` |
| 整行只有注释（`//` 或 `/* */` 之内） | `comment` |

已正确处理：`/* ... */` 跨多行的块注释、字符串常量（如 `"http://x"` 不会被误判成注释）、字符常量、转义符 `\"`。

### Python

| 情况 | 归类 |
| --- | --- |
| 整行只有空白字符 | `blank` |
| `#` 开头的行、`''' """` 三引号块（文档字符串） | `comment` |
| 其余含有效代码的行 | `code` |

### 扩展名归属

| 语言 | 扩展名 |
| --- | --- |
| C | `.c` `.h` |
| C++ | `.cpp` `.cc` `.cxx` `.c++` `.hpp` `.hh` `.hxx` `.h++` `.inl` |
| Java | `.java` |
| Python | `.py` `.pyw` |

> `.h` 归到 C。如果你的作业约定 `.h` 算 C++，只需修改 `loc.cpp` 里
> `kLangExt` 这张表的两个位置即可（表格中 `LANG_C` 一行去掉 `"h"`，
> `LANG_CPP` 一行加上 `"h"`）。

### 自动跳过的目录

版本控制与构建产物目录不会被扫描：
`.git` `.svn` `.hg` `.idea` `.vs` `.vscode` `node_modules` `obj` `Debug` `Release` `build` `dist`，
以及所有以 `.` 开头的隐藏目录。修改 `kSkipDirs[]` 可自定义。

## 六、实现要点

1. **目录遍历**：Windows 用 `FindFirstFileA/FindNextFileA`，类 Unix 用 `opendir/readdir`，
   用显式栈做迭代式递归，避免深目录爆栈；跳过符号链接防止目录环死循环。
2. **逐行扫描**：按字符状态机走，维护 `inBlock`（块注释状态）与 `inLine`（行注释状态），
   进入字符串字面量时整体跳过，保证 `//` `/*` 出现在字符串里时不被误解。
3. **大文件友好**：`std::getline` 流式读取，不一次性载入整个文件。
4. **跨平台换行**：二进制方式读取并手工去掉 `\r`，CRLF/LF 混用都能正确统计。
5. **路径拼接**：统一走 `joinPath()`，绝不产生重复分隔符。
   Windows 的长路径前缀会关闭系统路径规范化，一旦拼出双反斜杠
   会直接报 `ERROR_INVALID_NAME`，表现为整棵子树静默漏统计（扫描盘符根目录时最容易踩到）。

## 七、运行时可能出现的提示

以下信息输出到 **stderr**，不影响 stdout 的统计表格，重定向时不会污染结果文件：

| 提示 | 含义 |
| --- | --- |
| `N 个文件扫描结束时注释状态未闭合` | 文件本身语法不完整（如块注释没写 `*/`），该文件统计可能不准 |
| `N 个文件无法打开，已跳过` | 权限不足或被占用 |
| `目录数量达到上限` | 触发了兜底保护，结果可能不完整 |

正常情况下（例如扫描整个 C 盘）这三条都不会出现。
